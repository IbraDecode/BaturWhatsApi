# Security audit — 2026-09-23 (v0.1)

Scope: whole repository. Method: dependency inventory, threat checklist
(prompt §34), code review of auth/crypto/secrets paths.

## Inventory

- Third-party dependencies: NONE (go.mod requires only the module itself).
  Supply-chain surface = Go toolchain + stdlib only.
- Build: CGO_ENABLED=0 binaries; release workflow cross-compiles
  reproducibly from source (no build-time fetching beyond `go mod`).

## Checklist findings

| Area | Status | Notes |
|------|--------|-------|
| Authentication (API) | ✅ | bearer token, sha256 + constant-time compare; non-local bind refuses without token; /v1/health public by design (no secrets) |
| Authorization | 🟡 | single-token model = flat admin scope; multi-tenant authz is backlog (T-2xx) |
| Session isolation | ✅ | per-session conn/cipher/FSM/storage prefix; race-tested |
| Secrets at rest | 🟡 | credentials + ratchet state in file store (0600/0700 dir 0700); plaintext (documented: treat data dir as secret material). Encryption-at-rest keys = backlog |
| Crypto state | ✅ | counters monotonic, nonce reuse impossible by construction; tamper tests |
| Crypto primitives | ✅ | stdlib only; HKDF RFC vectors; Noise chain per spec; DR symmetry proven by cross-ratchet tests |
| Storage | ✅ | traversal-safe keys, atomic rename; manifest rebuild |
| Logging | ✅ | no secrets in logs (lengths/tags only); slog default level Info |
| Filesystem | ✅ | dirs 0700 / files 0600 |
| Network | ✅ | client role only; TLS via stdlib; WS masking; frame-size caps (16 MiB); no server exposure except opt-in API bind |
| DoS guards | ✅ | skip-map bound (1000), per-subscriber queues w/ drop policy, read deadlines |
| Event bus | ✅ | panic isolation verified by tests |
| Wire inputs | ✅ | decoder fuzz + truncation tests; malformed pb rejected |

## Open risks (tracked)

1. First-contact MITM window until production dial path pins
   `wacert.RootPubKey` by default (T-103 wiring).
2. Flat API token → add scopes before multi-tenant deployments (T-202+).
3. No at-rest encryption of the data dir yet.

Audit verdict: **v0.1 acceptable for development/testing use.** Production
messaging requires items 1-3 plus live-server verification (T-102).
